# Backend MVP Plan

## MVP Goal

> **A user can create an account, log in, answer a few questions about their trip, and receive a real personalized day-by-day itinerary generated by AI — then export it directly to their Google Calendar.**

The full flow must work end-to-end:
`Register/Login` → `/clarification/start` → multi-round Q&A → `/orchestrator/run` → research → planner → structured itinerary → **Google Calendar export**

#### 1. Database + User Model

Set up a relational database (PostgreSQL recommended) with SQLAlchemy ORM.

**Schema:**

```
users
├── id              UUID, primary key
├── email           string, unique, not null
├── hashed_password string, not null
├── display_name    string
├── created_at      timestamp
└── updated_at      timestamp

sessions (clarification sessions)
├── id              UUID, primary key
├── user_id         UUID, foreign key → users.id
├── destination     string
├── status          enum: active | complete | expired
├── clarification_data  JSONB  (ClarificationOutputV2 snapshot)
├── created_at      timestamp
└── updated_at      timestamp

itineraries
├── id              UUID, primary key
├── user_id         UUID, foreign key → users.id
├── session_id      UUID, foreign key → sessions.id
├── title           string
├── destination     string
├── start_date      date
├── end_date        date
├── data            JSONB  (PlannerOutputV1 snapshot)
├── created_at      timestamp
└── updated_at      timestamp

google_calendar_exports
├── id              UUID, primary key
├── user_id         UUID, foreign key → users.id
├── itinerary_id    UUID, foreign key → itineraries.id
├── calendar_id     string  (Google Calendar ID)
├── exported_at     timestamp
└── event_ids       JSONB   (list of created Google Calendar event IDs for future updates/deletes)
```

**Files to create:**
- `agents/core/database.py` — SQLAlchemy engine + session factory
- `agents/models/user.py` — User ORM model
- `agents/models/session.py` — ClarificationSession ORM model
- `agents/models/itinerary.py` — Itinerary ORM model
- `agents/models/calendar_export.py` — GoogleCalendarExport ORM model
- `alembic/` — Database migrations

#### 2. Authentication

Implement email/password auth with JWT access tokens.

**Flow:**
- `POST /api/auth/register` — Create user, return JWT
- `POST /api/auth/login` — Verify credentials, return JWT
- `GET /api/auth/me` — Return current user from token
- All protected routes use a `get_current_user` dependency via `Depends()`

**Implementation:**
- Hash passwords with `bcrypt` (`passlib`)
- Sign JWTs with `python-jose`, short-lived access tokens (15–60 min)
- `get_current_user` dependency reads `Authorization: Bearer <token>` header and returns `User` or raises 401

**Files to create:**
- `agents/core/security.py` — Password hashing, JWT encode/decode
- `agents/core/dependencies.py` — `get_current_user`, `get_db` FastAPI dependencies
- `agents/api/auth.py` — Register, login, /me endpoints

---

#### 3. Tie Sessions + Itineraries to Users

Once auth exists, all clarification sessions and itineraries must be owned by a user.

- `POST /api/clarification/start` — requires auth, creates a `sessions` row linked to `user.id`
- `POST /api/orchestrator/run` — requires auth, saves returned itinerary to `itineraries` table
- `GET /api/itineraries` — list all itineraries for the current user
- `GET /api/itineraries/{id}` — retrieve a specific itinerary (must belong to current user)

---

#### 4. LLM-Powered Research Agent (`agents/research/nodes/research.py`)

Replace the hardcoded generic POI list with a real LLM call that:
- Uses destination, destination_cities, and activity preferences from clarification output
- Generates a diverse, contextually relevant list of POIs with specific names
- Includes price level, duration estimate, and category per POI
- Output validates against `ResearchOutputV1` contract
- *(External API calls like Google Places are post-MVP — LLM-generated POIs are sufficient)*

---

#### 5. LLM-Powered Planner Agent (`agents/planner/nodes/planner.py`)

Replace the hardcoded generic event cycle with a real LLM call that:
- Reads the clarification output (preferences, pace, must-dos, budget, party, dates)
- Reads the research output (available POIs)
- Generates a day-by-day itinerary with real event names, times, and durations
- Respects constraints: mobility level, dietary restrictions, budget priority, pace preference
- Output validates against `PlannerOutputV1` contract

---

#### 6. Pass Clarification Output into Orchestrator (`agents/graph/orchestrator_api.py`)

The `/api/orchestrator/run` endpoint must:
- Accept a `session_id` and look up the completed clarification output from the database
- Pass `ClarificationOutputV2` through `OrchestratorState` to both research and planner nodes
- Persist the returned itinerary to the `itineraries` table
- Return the structured itinerary to the frontend

---

#### 7. Google Calendar Export

Allow the user to push a saved itinerary to their Google Calendar.

**OAuth Flow:**
- `GET /api/calendar/auth` — Redirect user to Google OAuth consent screen (scopes: `calendar.events`)
- `GET /api/calendar/callback` — Handle OAuth callback, store access + refresh tokens against the user record (add `google_access_token`, `google_refresh_token`, `google_token_expiry` columns to `users`)
- `POST /api/calendar/export/{itinerary_id}` — Export itinerary events to the user's Google Calendar

**Export Logic (`agents/services/calendar_service.py`):**
- For each `Day` in the itinerary, create a Google Calendar event per `Event` entry
- Set `start`/`end` times from the event's scheduled time and duration
- Set `description` to include event notes, address, price estimate
- Store created `event_id`s in `google_calendar_exports` table (enables future update/delete)
- Handle token refresh automatically using the stored refresh token

**Files to create:**
- `agents/api/calendar.py` — Auth redirect, callback, export endpoints
- `agents/services/calendar_service.py` — Google Calendar API client wrapper
- Add `google_*` columns to `users` table via migration

## Verification (End-to-End Test)

```bash
# 1. Register a user
curl -X POST http://localhost:8000/api/auth/register \
  -d '{"email": "test@example.com", "password": "secret123"}'

# 2. Log in, get JWT
curl -X POST http://localhost:8000/api/auth/login \
  -d '{"email": "test@example.com", "password": "secret123"}'
# → save TOKEN

# 3. Start clarification (authenticated)
curl -X POST http://localhost:8000/api/clarification/start \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"destination": "Tokyo", "dates": "April 10-17 2026", "budget": "2000", "currency": "USD", "travel_party": "couple"}'
# → save SESSION_ID

# 4. Complete clarification rounds
curl -X POST http://localhost:8000/api/clarification/respond \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"session_id": "$SESSION_ID", "response": "..."}'

# 5. Run orchestrator — returns real AI-generated itinerary
curl -X POST http://localhost:8000/api/orchestrator/run \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"session_id": "$SESSION_ID"}'
# → save ITINERARY_ID

# 6. Export to Google Calendar
curl -X POST http://localhost:8000/api/calendar/export/$ITINERARY_ID \
  -H "Authorization: Bearer $TOKEN"
# → Google Calendar events created for each day/event in the itinerary
```
